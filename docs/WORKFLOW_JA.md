# ワークフローの使い方

## 入力フォルダー

| 説明用パス | 中身 |
|---|---|
| `D:\CSIM_demo\reference` | 基準にする同一人物の写真 |
| `D:\CSIM_demo\different_people` | 基準人物とは異なる人の写真 |
| `D:\CSIM_demo\images` | 今回評価したい写真 |
| `D:\CSIM_demo\external` | external_folder使用時の、基準作成とは別の本人写真 |
| `D:\CSIM_demo\results` | JSONの保存先 |

これらのフォルダーを自動作成するセットアップではありません。入力フォルダーを用意し、全入力・JSON出力パスを自分の環境の絶対パスに変更してください。Dドライブがない環境でも変更して使えます。

## 基準と物差し

Referenceは、検出できた顔の特徴ベクトルを平均・正規化して本人の基準を作ります。表示する平均顔の画像を、そのまま一致度の計算に使うわけではありません。

Rulerの `same_person_mode` は、本人側のスコアをどの画像で測るかの指定です。

- `leave_one_out_reference`：基準写真から1枚を取り出し、その1枚を除いた残りで基準を作って、取り出した1枚を採点。すべての写真について繰り返します。最初はこの設定で進められます。
- `external_folder`：基準作成用とは別の本人写真を `same_person_dir` に指定し、Referenceと比較します。Referenceと同じ写真を重ねて使うとスコアが高めになります。

`threshold_mode` は、本人・別人の判定境界の決め方です。

- `distribution`：本人スコアの5パーセンタイルと別人スコアの95パーセンタイルを使います。0.80／0.50の入力値を判定境界として使う方式ではありません。
- `normalized_manual`：本人側・別人側の平均を基に正規化したスコアへ、手入力の境界を適用します。例は本人0.80以上、別人0.50以下です。正規化スコアは確率ではなく、0〜1を超えることもあります。

本人側と別人側の分布が重なる場合、物差しが十分に分離できていません。グラフと使った写真を確認してください。モデル比較では、Reference・Ruler・backend等の条件を統一します。

## 動画

Load Videoから読み込むフレーム列を、本人評価と色評価に共通で渡します。動画をFPS変更・間引きした場合、評価側のFPSもそのフレーム列に合わせて変更してください。

全フレーム評価と20〜30秒の区間集計は別です。本人保持率を見るときは、JSONの `evaluation_window` を確認し、評価フレーム数・本人判定フレーム数・検出できないフレームも区別します。代表画像の5秒間隔は、全フレームの本人評価を5秒間隔だけにする指定ではありません。

肌色の評価はCIEDE2000色差です。画面全体・衣服・背景の色保持ではありません。正面は両頬、斜めは可視側の頬を使い、横顔・肌マスク不足等は保留になります。配布設定では本人判定も評価条件に使います。照明の変化も色差に影響するため、グラフと元映像を合わせて確認します。

## JSON

| ファイル名の基本形 | 保存する内容 |
|---|---|
| `id_reference.json` | 基準人物の特徴・検出結果・各画像の特徴ベクトル |
| `id_ruler.json` | 本人／別人の校正結果と判定境界 |
| `id_image_results.json` | 評価画像ごとの一致度・判定 |
| `id_video_results.json` | 動画の本人一致度・時系列・区間集計 |
| `color_video_results.json` | 肌色の色差・保留理由・区間集計 |

動画のJSON名には、設定に応じて動画名や評価条件の識別子が追加されます。同じ保存先・同じ条件で再実行すると上書きされる場合があるため、比較対象ごとに保存先を整理してください。

AIに読ませる場合の依頼例:

> 対象動画、backend、判定方式、FPS、評価区間を先に確認してください。動画全体とevaluation_windowの結果を分け、本人一致度の低下、肌色の変化、評価できなかったフレームを整理してください。映像で確認すべき時刻を挙げ、JSONから分からない原因は断定しないでください。

外部AIへ渡す前に、ファイルパスや顔の特徴ベクトルなど、渡す必要のない内容を確認してください。
